What is the problem it actually solving?

There is a specific problem we encounter when building deep neural networks with multiple layers. For complex, real-world tasks, we often need deeper and more sophisticated models. Common sense suggests that if we make a neural network deeper, it should perform better. However, in practice, increasing the network's depth does not always improve performance; sometimes, it can actually make the network perform worse.

One of the reasons for this difficulty is the vanishing gradient problem, in which gradients become extremely small as they propagate backward through the network, making it difficult for earlier layers to learn effectively. Residual Networks (ResNets) address this issue by introducing residual connections, also known as skip connections, which provide more direct paths for gradient flow and make deep neural networks easier to optimize.

What is gradient?

A gradient is a value that tells us how much the loss function changes when the weights of a neural network change. It helps determine how much and in which direction the weights should be updated. A small gradient usually results in a small weight update, whereas a large gradient usually results in a larger weight update, assuming the learning rate remains the same.

What is vanishing gradient problem?

We train neural networks using backpropagation, during which the gradients are calculated from the last layer to the first layer, and the weights are updated based on these gradients. Now, if our neural network is deep, meaning it has many layers, the gradients have to pass through many layers during backpropagation. During this process, the gradients are repeatedly multiplied by derivatives of activation functions and other factors. These repeated multiplications can cause the gradients to become very small.

Now, very small gradients cause very small weight updates in the earlier layers, which means these layers learn very slowly or may stop learning effectively. This problem is called the vanishing gradient problem.

Idea of residual connection:

We saw previously how, in normal neural networks, gradients have to pass through multiple layers, which is why their values get very small and ultimately cause the vanishing gradient problem.

In residual connections, we use a special type of connection called a "skip connection" in the network. Instead of having to pass through every single layer sequentially, the gradients can take a shortcut across a block of layers. Because of this shortcut, the gradient values don't get crushed to zero, which prevents the vanishing gradient problem.

If we formalize a normal neural network, it becomes:

y = F(x)

Where:

  • F is the transformation function (the stacked layers in our model)
  • x is the given input
  • y is the output

If we provide an input (x) to our model (F), it will produce an output (y). But in a residual connection, this formula becomes:

y = F(x) + x

Here, adding back the input (x) is what creates the skip connection. During backpropagation, this identity path provides a direct route for gradients with a derivative of 1, ensuring they don't vanish even in very deep networks.

How we create residual network?

Residual networks are basically created by stacking multiple blocks named residual blocks. These residual blocks contain multiple layers with a residual connection, and we stack multiple of these residual blocks to form a deep residual network.

There are mainly three types of residual blocks: basic block, bottleneck block, and pre-activation block.

The first two are mostly used in ResNet architectures, and the third one is also used in pre-activation ResNets. A similar design, known as pre-normalization, is commonly used in Transformer-based models.

  1. Basic block: A basic block is the simplest building block used in the original ResNet architecture. This block consists of two sequential 3 × 3 convolutional layers and a residual connection. The input and output dimensions are usually equal. If their dimensions differ, a projection shortcut can be used to match them.
  1. Bottleneck block: A bottleneck block consists of three sequential convolutional layers and a residual connection. The first layer in this block is a 1 × 1 convolution for dimension reduction. The second layer performs a 3 × 3 convolution, and the last layer is another 1 × 1 convolution for dimension restoration or expansion. The exact amount of dimension reduction depends on the architecture. The ResNet-50, ResNet-101, and ResNet-152 models are all based on bottleneck blocks.
  1. Pre-activation block: The pre-activation residual block applies normalization and activation functions before applying the residual function (F). Formally, the computation of a pre-activation residual block can be written as:

xℓ+1​=F(ϕ(xℓ​))+xℓ​

where (\phi) represents normalization and activation operations, such as Batch Normalization followed by ReLU, and (F) represents the residual function.

This design reduces the number of non-identity mappings between residual blocks and allows an identity mapping directly from the input to the output. This improves gradient propagation and makes it easier to train very deep neural networks. Pre-activation ResNets were shown to perform well when training networks with hundreds of layers.

Since GPT-2, Transformer blocks have commonly used pre-normalization, in which normalization is applied before the attention and feed-forward sublayers. This design is conceptually similar to pre-activation ResNets, although the two are not exactly the same.

Implimentation of resnet-10 from scratch:

Theory:

We will follow the resnet-18 architechure and decrease the number of layer and create our own model resnet-10 from scratch and train it from scratch on the fashion-mnist dataset.

First, we will learn about the ResNet-18 architecture.

ResNet-18 stands for Residual Network with 18 layers. It is a convolutional neural network (CNN) that uses residual connections, also known as skip connections, to facilitate the training of deep neural networks.

ResNet-18 is built using BasicBlocks, which are the fundamental building blocks of the network.

The architecture consists of:

  • An initial 3 × 3 convolutional layer.
  • Four residual stages, with each stage containing two BasicBlocks.
  • One fully connected layer at the end for classification.

Each BasicBlock contains two main convolutional layers, along with Batch Normalization, ReLU activation, and a shortcut connection.

Counting the 18 Layers

Let's calculate the total number of layers:

  1. Initial convolutional layer: 1 layer.
  1. Four residual stages: Each stage contains two BasicBlocks, and each BasicBlock contains two convolutional layers.

    Therefore, the total number of convolutional layers in the residual stages is:

    4×2×2=16

  1. Final fully connected layer: 1 layer.

Hence, the total number of layers is:

Total layers=1+16+1

Total layers=18​

Therefore, ResNet-18 consists of one initial convolutional layer, 16 convolutional layers distributed across eight BasicBlocks, and one final fully connected layer.

For our resnet-10 model we have just removed the last two residual stages and that makes the total layers count to 10.

import torch

import torch.optim as optim
import torchvision
import torchvision.transforms as transforms

import matplotlib.pyplot as plt
import numpy as np

from torch.utils.data import DataLoader

# ============================================================
# 1. DEVICE CONFIGURATION
# ============================================================

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

# ============================================================
# 2. FASHION-MNIST DATASET

transform = transforms.Compose([

train_dataset = torchvision.datasets.FashionMNIST(

train_loader = DataLoader(

    shuffle=True,
    num_workers=0
)

test_loader = DataLoader(
    test_dataset,
    batch_size=128,
    shuffle=False,
    num_workers=0

class_names = [
    "T-shirt/top",
    "Trouser",
    "Pullover",

# ============================================================
# 3. RESNET-10 ARCHITECTURE
# ============================================================

class BasicBlock(nn.Module):
    expansion = 1

    def __init__(self, in_channels, out_channels, stride=1):
        super(BasicBlock, self).__init__()

        self.conv1 = nn.Conv2d(
            in_channels,
            out_channels,
            kernel_size=3,
            stride=stride,
            padding=1,
            bias=False
        )

        self.bn1 = nn.BatchNorm2d(out_channels)

        self.relu = nn.ReLU(inplace=True)

        self.conv2 = nn.Conv2d(
            out_channels,
            out_channels,
            kernel_size=3,
            stride=1,
            padding=1,
            bias=False
        )

        self.bn2 = nn.BatchNorm2d(out_channels)

        # Projection shortcut when dimensions change
        if stride != 1 or in_channels != out_channels:
            self.shortcut = nn.Sequential(
                nn.Conv2d(
                    in_channels,
                    out_channels,
                    kernel_size=1,
                    stride=stride,
                    bias=False
                ),
                nn.BatchNorm2d(out_channels)
            )
        else:
            self.shortcut = nn.Identity()

    def forward(self, x):
        identity = self.shortcut(x)

        out = self.conv1(x)
        out = self.bn1(out)
        out = self.relu(out)

        out = self.conv2(out)
        out = self.bn2(out)

        out = out + identity
        out = self.relu(out)

        return out


class ResNet10(nn.Module):
    def __init__(self, num_classes=10):
        super(ResNet10, self).__init__()

        # Initial convolution: 1 channel for grayscale images
        self.conv1 = nn.Conv2d(
            1,
            64,
            kernel_size=3,
            stride=1,
            padding=1,
            bias=False
        )

        self.bn1 = nn.BatchNorm2d(64)
        self.relu = nn.ReLU(inplace=True)

        # Stage 1: two BasicBlocks convolutions = 4 convolutions
        self.layer1 = self.make_layer(
            64, 64, stride=1
        )

        # Stage 2: two BasicBlocks convolutions = 4 convolutions
        self.layer2 = self.make_layer(
            64, 128, stride=2
        )

        self.avgpool = nn.AdaptiveAvgPool2d((1, 1))

        self.fc = nn.Linear(128, num_classes)

    def make_layer(self, in_channels, out_channels, stride):
        return nn.Sequential(
            BasicBlock(in_channels, out_channels, stride),
            BasicBlock(out_channels, out_channels, stride=1)
        )

    def forward(self, x):
        x = self.conv1(x)
        x = self.bn1(x)
        x = self.relu(x)

        x = self.layer1(x)
        x = self.layer2(x)

        x = self.avgpool(x)
        x = torch.flatten(x, 1)

        x = self.fc(x)

        return x

# 4. INITIALIZE MODEL, LOSS, AND OPTIMIZER
# ============================================================

model = ResNet10(num_classes=10).to(device)

criterion = nn.CrossEntropyLoss()

optimizer = optim.Adam(
    model.parameters(),
    lr=0.001

print(model)

total_parameters = sum(
    parameter.numel()
    for parameter in model.parameters()
    if parameter.requires_grad
)

print("Total trainable parameters:", total_parameters)


# ============================================================
# 5. TRAINING FUNCTION
# ============================================================

def train_one_epoch(model, loader, criterion, optimizer):
    model.train()

    running_loss = 0.0
    correct = 0
    total = 0

    for images, labels in loader:
        images = images.to(device)
        labels = labels.to(device)

        # Clear previous gradients
        optimizer.zero_grad()

        # Forward pass
        outputs = model(images)

        # Calculate loss
        loss = criterion(outputs, labels)

        # Backpropagation
        loss.backward()

        # Update weights
        optimizer.step()

        running_loss += loss.item() * images.size(0)

        _, predicted = torch.max(outputs, dim=1)

        total += labels.size(0)
        correct += (predicted == labels).sum().item()

    epoch_loss = running_loss / total
    epoch_accuracy = 100.0 * correct / total

    return epoch_loss, epoch_accuracy


# ============================================================
# 6. TESTING / EVALUATION FUNCTION
# ============================================================

def evaluate(model, loader, criterion):
    model.eval()

    running_loss = 0.0
    correct = 0
    total = 0

    all_labels = []
    all_predictions = []

    with torch.no_grad():
        for images, labels in loader:
            images = images.to(device)
            labels = labels.to(device)

            outputs = model(images)

            loss = criterion(outputs, labels)

            running_loss += loss.item() * images.size(0)

            _, predicted = torch.max(outputs, dim=1)

            total += labels.size(0)
            correct += (predicted == labels).sum().item()

            all_labels.extend(labels.cpu().numpy())
            all_predictions.extend(predicted.cpu().numpy())

    epoch_loss = running_loss / total
    epoch_accuracy = 100.0 * correct / total

    return (
        epoch_loss,
        epoch_accuracy,
        np.array(all_labels),
        np.array(all_predictions)
    )


# ============================================================
# 7. TRAINING LOOP
# ============================================================

num_epochs = 5

train_losses = []
test_losses = []

train_accuracies = []
test_accuracies = []

best_test_accuracy = 0.0

for epoch in range(num_epochs):

    train_loss, train_accuracy = train_one_epoch(
        model,
        train_loader,
        criterion,
        optimizer
    )

    test_loss, test_accuracy, _, _ = evaluate(
        model,
        test_loader,
        criterion
    )

    train_losses.append(train_loss)
    test_losses.append(test_loss)

    train_accuracies.append(train_accuracy)
    test_accuracies.append(test_accuracy)

    print(
        f"Epoch [{epoch + 1}/{num_epochs}] "
        f"| Train Loss: {train_loss:.4f} "
        f"| Test Loss: {test_loss:.4f} "
        f"| Train Accuracy: {train_accuracy:.2f}% "
        f"| Test Accuracy: {test_accuracy:.2f}%"
    )

    # Save the best model based on test accuracy
    if test_accuracy > best_test_accuracy:
        best_test_accuracy = test_accuracy

        torch.save(
            model.state_dict(),
            "best_resnet10_fashion_mnist.pth"
        )

Conclusion:

In conclusion, residual connections make it possible to build and train very deep neural networks more effectively by improving gradient flow and addressing some of the optimization difficulties associated with increasing network depth. The success of residual connections has influenced the development of many modern deep learning architectures. They are still widely used today, including in Transformer architectures, where skip connections help facilitate the training of deep networks.

Overall, understanding residual connections provides a strong foundation for learning more advanced deep learning architectures. The concept of residual learning remains an important contribution to modern neural network design, helping researchers develop deeper and more capable models.
